# Video Jukebox: from a NASA video to music

**English** · [Español](README.es.md)

Turns a map video (equirectangular, like those from the SVS / Earth Information Center) into a
4-track MIDI file for the Yamaha DX7 (Dexed), plus a preview you can listen to right away.

Reference example: `ecco2_sst_flow.mp4` (ocean currents + sea temperature, SVS 3912).

## Install and run

```bash
# from the repository root (Python 3.10+; ffmpeg installed on the system)
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r video_jukebox/requirements.txt
cd video_jukebox
PATH="../.venv/bin:$PATH" ./run.sh ecco2_sst_flow.mp4 oceano     # ~1-2 min
```

Output in `out/` (not committed to git):

| File | What for |
|---|---|
| `oceano_features.npz` | features per frame and band (step 1) |
| `oceano.mid` | open in a DAW (Reaper, LMMS, Ardour) with one Dexed instance per track |
| `oceano_events.json` | notes in beats, as generated by the composer (for the preview) |
| `oceano_timeline.json` | features + notes in seconds, validated, **for the web interface** |
| `oceano_preview.wav` | audio from the simple FM synthesizer (not Dexed, just for checking) |
| `oceano_preview.mp4` | the video with that audio |

Or step by step:
```bash
python analyze.py video.mp4 features.npz
python compose.py features.npz salida.mid --events events.json
python export_timeline.py features.npz events.json timeline.json --source video.mp4
python render_preview.py events.json preview.wav
```

## How it works (4 steps)

```
video.mp4 ──► analyze.py ──► features.npz ──► compose.py ──► salida.mid ──► Dexed
              (WHAT happens) (numbers per       (HOW it      events.json ──► render_preview.py (preview)
                              frame and band)    sounds)  │              │
                                    └────────────────┴──► export_timeline.py ──► timeline.json (web)
```

### 1. `analyze.py`: what happens in the video
Splits the map into 5 latitude bands (Arctic, northern mid-latitudes, tropics, southern
mid-latitudes, Antarctic). In each frame and each band it measures:

| Measure | How | What it is (visual proxy) |
|---|---|---|
| `temp` | pixel hue (blue=0 … red=1) | position in the color palette; it suggests temperature, **it is not °C** |
| `speed` | optical flow (OpenCV Farneback), px/frame | apparent motion of the lines, **not m/s** |
| `u`, `v` | flow components, px/frame | apparent direction (east/west, north/south) |
| `vort` | curl of the flow | apparent eddies in the image, not physical vorticity |
| `cover` | % of valid pixels | how many colored pixels the band has (not the real % of ocean) |

Land (gray) and the dark background are ignored with a saturation/brightness mask.
All of them are **pixel-derived** measures: they depend on the palette, the compression, the
analysis resolution (`--width`) and the speed of the animation. They make the music follow what
you see; they are not calibrated scientific data. If a band has fewer than `MIN_PIXELS` (50)
valid pixels its measures are set to 0; `band_pixels` (pixels per band) tells that case apart
from a real 0.

### 2. `compose.py`: how it sounds
- **Harmonic director:** the north−south thermal contrast (the seasons) picks the chords, dark in
  the boreal winter and bright in the summer. Every voice plays ONLY notes of the current chord:
  the harmony holds even if the data is chaotic.
- **Tempo:** 90 BPM → 1 beat = 20 frames at 30 fps. The data is smoothed (median + 1 s mean) and
  averaged per beat. If `fps × 60 / bpm` is not an integer, the tempo is adjusted to the nearest
  whole number of frames per beat (e.g. 25 fps and 90 BPM → 17 frames → 88.24 BPM) so the music
  does not drift from the video; `events.json` stores `bpm` (the one used) and `bpm_requested`.

| Channel | DX7 instrument | Data |
|---|---|---|
| 1 | STRINGS 1 | chords per bar; volume = global temperature |
| 2 | FLUTE 1 | one voice per band (north = high); it plays if the current speeds up; the band's temperature moves the note; turbulence controls the timbre (CC1) |
| 3 | TUB BELLS | a bell strike at each vorticity peak (eddy) |
| 4 | BASS 1 | chord root; more notes the stronger the equatorial current flows west |

Everything that can be tuned is in the **CONFIGURACIÓN** block at the start of `compose.py`
(tempo, chords, instruments, register of each band).

### 3. `render_preview.py`: listening without Dexed
A 2-operator FM synthesizer (the DX7 principle) + reverb. Only for checking the mapping.

```bash
python render_preview.py events.json preview.wav --stems out/stems   # mix + 4 tracks
```

With `--stems DIR` it also writes `DIR/<track>.wav` (`temperatura`, `corrientes`, `remolinos`,
`ecuatorial`) and `DIR/stems.json` (gain, peaks and first note of each track). The `preview.wav`
mix is byte-for-byte identical to before. The stems:

- come from the same voice generator as the mix: same length, same start (sample 0), and each
  track's first note lands on the same sample as in the mix;
- are linear (without the mix's `tanh` saturation) and share **a single gain**, chosen so that
  none of the 15 mute/solo combinations goes above −1 dBFS; this keeps the balance between
  instruments, and the sum of the stems is the mix before saturation.

Tests: `tests/test_render_preview.py`.

## Web assets (`build_web.py`)

Prepares the `web/jukebox.html` demo from what `run.sh` already generated
(`out/<name>_events.json` and `out/<name>_timeline.json`) and from the original video:

```bash
cd video_jukebox
python build_web.py --name ecco2_full --video ../data/media/ecco2/ecco2_sst_flow.mp4 \
    --dates ../data/media/ecco2/flat_ecco2_dates.txt          # ~30 s; --skip-video reuses the video
python build_web.py --name ecco2_full --check-only            # only validates what is already written
```

It writes to `web/public/` (these files **are** committed to git, for GitHub Pages):

| File | How | Size (ECCO2) |
|---|---|---|
| `media/jukebox/ecco2.mp4` | H.264 1280×640, 2-pass at 1200 kb/s, GOP 30 (fast seeking), no audio, `+faststart` | 10.0 MB |
| `media/jukebox/ecco2_<track>.m4a` ×4 | FM preview stems, AAC 128 kb/s | 0.8–1.1 MB each |
| `data/jukebox/ecco2_timeline.json` | the timeline, minified | 0.55 MB |
| `data/jukebox/ecco2.json` | manifest: relative paths, duration, colors, DX7 instruments, model dates, NASA credits | 4 KB |

Total 14.7 MB. The WAV files, the `.npz`, the original videos and the figures stay in `out/` and
`data/media/` (ignored by git).

Before finishing it validates and aborts if anything fails: relative, existing paths (they work
under `https://<user>.github.io/SpaceAppChallenge2026/`), FPS, frames and no audio in the video,
that each decoded stem starts on the same sample as the WAV (zero offset) and is not shorter than
the music, that no track combination clips, size budgets and NASA/ECCO2 credits. It prints the
quality of each stem (SNR against the WAV). Tests: `tests/test_build_web.py` (6 s synthetic video).

**Stem quality.** `compare_stems.py` compares each WAV with its published AAC at equal loudness
(per band, in the attack and in the decay of the bells), and with `--excerpt 8` writes A/B
excerpts to `out/compare/`:

```bash
python compare_stems.py --name ecco2_full --also 192 256 --excerpt 8
```

With ECCO2 at 128 kb/s: temperature, currents and bass stay at 34–40 dB SNR. The bell
(`remolinos`) stays at 13 dB because the FM patch (ratio 3.5, index 4) has 5.7 % of its energy
above 16 kHz and the encoder cuts at 17.6 kHz; the error is also concentrated in the attack
(9 dB versus 17 dB in the decay). In the highest notes (≥ 88, 25 of 69 bell strikes) part of that
content is aliasing from the synthesis itself (−7 dB at note 98). At 256 kb/s there is no cutoff
and the SNR rises to 34 dB.

Trying the demo:

```bash
cd web && npm ci
npm run dev                         # http://localhost:5173/jukebox.html
npm run build && npx vite preview --base /SpaceAppChallenge2026/   # as on GitHub Pages
```

### Using the demo

- **Language.** English by default; the *English / Español* switch in the header changes the whole
  page (including dates, decimal separators and screen reader texts) without stopping the music.
  The choice is stored in the browser; `?lang=es` or `?lang=en` in the URL forces it.
- **Playback.** The audio is the clock and the video follows it. Use the button or `Space`; `←`/`→`
  jump 5 s; `Home`/`End`. Clicking the piano roll or a chart jumps to that moment.
- **Tracks.** Mute with `1`–`4`, solo with `Shift`+`1`–`4`, unmute all with `0`.
- **Piano roll and charts from the keyboard.** They are sliders: with focus, the arrow keys move
  one beat (piano roll) or 1 s (charts), `Page Up`/`Page Down` one bar or 10 s, `Home`/`End`. Screen
  readers announce the time, the chord and the notes, or the value and unit of the measure.
- **If the video gets stuck** (slow network, a jump to a part that is not downloaded, an error), the
  music stops at that point and a notice explains what is happening. If the video recovers, playback
  continues on its own; if it keeps freezing or there is an error, the *Retry* button reloads the
  video and continues from the same point.
- **Visual proxies.** The charts are indices computed from the video's pixels: they are not °C, m/s
  or physical vorticity (see [`docs/ECCO2_VALIDATION.md`](../docs/ECCO2_VALIDATION.md)).

### 4. `export_timeline.py`: data for the web
Joins `features.npz` and `events.json` into a JSON with everything in seconds:

| Key | Contents |
|---|---|
| `timing` | `fps`, `frames`, `bpm`, `seconds_per_beat`, `frames_per_beat`, `beats`, `bars`, video and music durations |
| `regions` | the 5 bands with their latitudes |
| `channels` | the 4 channels (`temperatura`, `corrientes`, `remolinos`, `ecuatorial`) with MIDI channel and DX7 program |
| `features.t` | time of each frame: `(row + 1) / fps` (row 0 is frame 1: optical flow needs two frames) |
| `features.metrics` | per measure: `unit`, `derived_from`, `caveat`, `nature: "visual_proxy"`, `calibrated: false` and `by_region` = one series per band (`null` = no data) |
| `notes` | `t`, `dur` (s), `beat`, `dur_beats`, `channel`, `track`, `note`, `vel`; `t = beat × 60 / bpm`, same as the MIDI |
| `chords`, `cc` | chord of each bar and controllers (CC1 timbre, CC11 expression), with their `t` |
| `validation` | `status` (`ok` / `warnings`), list of warnings and numeric summary |

**Validation.** It aborts (exit code 1, writes nothing) if measures are missing, the shapes are not
`(frames, 5)`, the regions are not those of `analyze.py`, the FPS or the BPM are invalid, or if
`events.json` does not come from that `features.npz` (its `fpb`/`nbeats` do not match). It warns,
without aborting, about: frames without data or non-finite values (exported as `null`), mean
coverage < 2 %, music–video drift, odd frames per beat and notes that start after the end.

**Music–video drift.** `notes[].t` follows the audio clock and `features.t` the video clock. With
the adjusted tempo from `compose.py` they match; the drift warning fires with `events.json` files
generated by older versions (which used the nominal BPM: at 25 fps and 90 BPM they drifted by
~1.2 s per minute).

## Adding another kind of video (lights, CO2, wind, ice…)

1. **Copy `analyze_plantilla.py`** (e.g. `analyze_luces.py`) and change only the `medir()` function.
   It already includes example measures: `brillo` (brightness), `nuevas` (lights that appear),
   `color` and `cambio` (change).
   - Night lights → `brillo` and `nuevas`; mask = the whole map
   - CO2 / temperature in colors → `color`
   - Wind / currents → use `analyze.py` directly (optical flow)
   - Ice → `brillo` (white) or the % of white pixels per band
2. **Check the numbers** before making music: plot each measure per band and verify that it makes
   sense (seasons, regions). If it does not, the music will not either.
3. **In `compose.py`, add a voice** like the existing ones: read your measure, normalize it with
   `norm01()`, pick the note with `nearest_chord_tone()` (so it respects the harmony) and add the
   track to `TRACKS`. One instrument per category (lights → bells, wind → flute, etc.).
4. By using the **same director** (tempo and chords) for every category, the tracks can be combined
   into a single MIDI file and will sound together.

## Video requirements
- **Equirectangular** projection (2:1 rectangular map, north up). SVS pages usually have a version
  like this ("equirectangular" or for Science On a Sphere).
- Preferably **without text, date or color bar** on top. If it has them, crop or mask them first.
